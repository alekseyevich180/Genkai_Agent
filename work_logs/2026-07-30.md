## 论文到 UMA 表面反应微调工作流连通性检查

使用已有论文 `s41467-025-56361-4.pdf` 对以下链路进行了隔离检查：

```text
PDF 摄取
-> 已保存抽取结果回放
-> PToModel
-> 表面/团簇/吸附结构生成
-> DFT 输入占位与模拟标签
-> UMA 数据审计
-> ASE-LMDB 转换
-> UMA 训练 dry-run
```

测试产物位于：

`/tmp/genkai_paper_to_uma_20260730_5JuX20/`

本次没有执行真实第一性原理计算、UMA 训练、GPU 计算或 PJM 提交。

### 已验证的连通环节

- `python -m paperread.surface ingest` 能从 PDF 生成文本、章节和后续抽取输入。
- 为避免重新调用外部 LLM，使用同一论文已保存的 conditions、relations、summary
  和 time 产物回放 PToModel；没有验证本次环境中的在线语义抽取。
- PToModel 成功生成 `replay_ptomodel.json`，将
  `adsorbate_landscape` 和 `surface_cluster_builder` 标为 executable，
  `doped_surface` 和 `slab_generation` 仍为 deferred。
- 实际生成了 Ni13/CeO2(111) 支持团簇和 4 个吸附候选，搜索使用
  `calculator=none`，输出能量只用于工作流测试。
- 使用明确标记为 `MOCK_NOT_DFT` 的模拟能量和力验证了 UMA `ef` 数据接口。
- 原微调脚本能够完成数据审计、ASE-LMDB 转换以及训练启动 dry-run。

### 发现的问题

1. 论文没有给出 CeO2 晶面、Ni 团簇原子数或解析后的粒子结构；CeO2(111)、
   fcc-Ni13 和双 Ni 位点均为人工演示假设，不能作为论文直接结论。
2. 当前 paperread/PToModel/surface-modeling 只能形成吸附、覆盖度和支持团簇候选，
   尚不能自动构造反应物、中间体、产物、过渡态或 NEB 路径。仅有吸附候选不足以
   建立表面反应微调数据集。
3. `agents/Agent/skills/vasp/scripts/vasp_tools.py` 在模块顶层强制导入
   `dpdata`。当前项目 Python 环境缺少该依赖，因此连 `--help` 和
   `prepare_relaxation` 都无法进入；本次只用 ASE 生成了无 POTCAR、OUTCAR 和
   `vasprun.xml` 的输入占位文件，状态明确为 `NOT_RUN`。
4. 原 UMA 审计对三个最短距离为 `0.260536 Ang` 的严重重叠结构只给 warning，
   仍允许继续转换。这类结构不应进入 DFT 队列或微调数据。
5. 原审计只检查 train/validation，不检查保留的 test 数据及其跨 split 精确泄漏。
6. 原准备脚本允许选择 `oc22`，但本机 `fairchem-core 2.21.0` 的便捷转换器实际
   不接受 `oc22`。不能通过把 PBE+U 数据改标为 `oc25` 来绕过限制。
7. 原转换流程结束后没有自动检查非空 `*.failed`、ASE-LMDB 回读或 Hydra
   配置组合，转换命令返回 0 还不足以证明训练输入可用。
8. 即使格式审计通过，脚本仍不能证明 DFT 收敛、单位与理论水平一致、轨迹分组
   正确或反应路径覆盖充分；这些信息仍需 provenance metadata 和人工审查。
