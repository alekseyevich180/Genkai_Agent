**Goal:** 在不启动 VASP、DFT、MLIP、结构弛豫、GPU/PJM、训练或 MD 的前提下，
把已保存的论文抽取结果安全地连接到表面结构生成算法，产出 ASE 可读且登记到
`RunManifest` 的真实 `StructureSetArtifact`。

**Architecture:** 保留 `build_surface_candidates()` 的 prepare-only 兼容语义，新增
显式的 structure-only 执行器。执行器只允许稳定库中的白名单 callable，先检查
PToModel checklist，再通过用户覆盖值或可验证的上游结构解析器补齐输入；无法安全
确定的晶面、分子结构、覆盖度和 SAM 构型必须阻断，不能根据论文措辞猜测。

**Tech Stack:** Python 3.12、Pydantic artifact contracts、ASE、pymatgen、
Materials Project API、Click、pytest。

## Global Constraints

- 本实施计划的默认运行模式只能是 `prepare` 或 `structure-only`。
- `structure-only` 必须固定使用 `calculator=none` 和 `max_steps=0`。
- 不执行 VASP、DFT、MACE、UMA、DeepMD、结构弛豫、训练、MD、GPU 或 PJM。
- Materials Project API key 只从环境读取，不能写入 manifest、日志或命令输出。
- 论文仅观察到的晶格面不能自动当作暴露表面；必须由明确的 exposed-facet 证据或
  用户覆盖值确认。
- “incomplete coverage”等定性描述不能自动转换为 `coverage_counts`。
- 默认 `genkai-workflow surface run` 行为保持 prepare-only，只有显式指定
  `--modeling-mode structure-only` 才生成结构。
- 第一阶段只打通 `adsorbate_landscape`；`surface_functionalization` 和通用 SAM
  构建继续返回明确的 unsupported/blocking 结果。
- 所有新逻辑采用 TDD；外部网络测试不得进入默认 pytest 集合。

## 当前问题与根因

### 1. PDF 主工作流在建模准备层停止

`src/genkai/workflows/paper_to_mlip.py::initialize_paper_to_mlip_run()` 已形成：

```text
relation extraction
-> build_modeling_plan()
-> build_surface_candidates()
```

但 `build_surface_candidates()` 的契约就是 prepare-only：

- docstring 明确写明不调用 Skill/算法；
- 输出 `execution_state=prepared`；
- 输出 `structures=[]`；
- artifact metadata 为 `structure_count=0` 和
  `contains_command_plan_only=true`。

因此这不是表面建模算法运行失败，而是缺少 plan-to-callable 执行层。

### 2. Canonical schema 只有入口描述，没有调度器

`src/genkai/modeling/schema/task_parameter_schema.json` 已记录：

```json
{
  "adsorbate_landscape": {
    "script": "genkai.modeling.surface.adsorbate:main"
  }
}
```

当前没有代码读取 `script` 字段、校验参数、导入 callable、执行算法并收集返回产物。
不能直接对该字符串做任意动态 import；下一步应建立显式白名单 registry。

### 3. 当前论文的必需参数仍未解析

`modeling/checklist.json` 当前为 `needs_review`：

- `surface=null`，依赖真实 slab；
- `molecule=null`，依赖真实分子坐标；
- `coverage_counts=null`，定性 incomplete coverage 不能唯一确定数值；
- 自动得到的 `site_symbols="Sn,S"` 含错误的 `S` 候选，本次运行人工限制为 `Sn`。

### 4. 上游任务没有进入可执行集合

PToModel 支持识别 `slab_generation` 和 `surface_functionalization`，但当前
`EXECUTABLE_TASKS` 只有：

- `vacancy_landscape`；
- `adsorbate_landscape`；
- `surface_cluster_builder`。

Materials Project slab helper 已存在，但尚未注册进 plan executor；通用
PAC12IMI/PAC10CA/PAG3 SAM 构建算法尚不存在。

### 5. 论文关系没有转成任务优先级

论文主要选择性关系是 PAC12IMI—acetone 和 PAC10CA—CH4，但当前
`adsorbate_species` 保留抽取列表顺序，自动测试因而首先选择 H2。下一步不能仅取
第一个 adsorbate；必须保留并使用 modifier—adsorbate 关系，或要求用户选择目标对。

### 6. 手动生成结构没有回写统一 artifact

本次 slab 和 6 个候选结构保存在 `automatic_modeling/`，但没有更新第三阶段的
`StructureSetArtifact`。下游 MACE adapter 仍读取 `candidates.json`，因此报告：

- JSON 不是 ASE 结构文件；
- structure set 为空；
- MACE launcher 需要一个 ASE 可读输入文件。

正确实现应把候选结构汇总成一个 `extxyz`，登记逐文件 hash/inventory，并将第三阶段
状态更新为 `succeeded`。

### 7. JSONL 写入和读取契约仍需回归保护

关系抽取器会把 pretty-printed 多行 JSON 写入 `.jsonl`，而部分旧读取路径按物理行
调用 `json.loads()`。PToModel 当前的 raw decoder 能读取连续 JSON，但其它读取器仍
可能失败。本次生成了 compact 单行恢复文件继续测试；下一步应统一为真正的一行一条
JSONL，并保留对历史多行文件的兼容读取测试。
