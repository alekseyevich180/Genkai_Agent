## 当前暴露出的关键问题：材料建模映射仍然过粗

`tests/test2.pdf` 对应论文不是简单的“Ni 材料”案例，而是更具体的：

- Ni 单原子位点
- 载体/基底为 graphene-like carbon
- 配位环境是 O 配位
- 实际研究对象更接近 `Ni-O_x` coordination on carbon-supported single-atom site

当前 `ptomodel` 虽然已经能提取：

- `single_atom_species = Ni`
- `supports_or_surfaces = Ni-O-G SACs / graphene-like carbon`
- `material_classes = single_atom_catalysts / carbon_materials / metals_alloys`

但对下游建模来说，这仍然不够。原因是：

- `primary_material = nickel` 过于粗糙，丢失了“单原子 + 碳载体 + O 配位”这三个关键约束。
- `surface-modeling` 当前也没有“单原子配位环境模板”这一层桥接接口，无法直接把论文中的 `Ni-O-G SACs` 转成明确的结构生成任务。
- `facet`、`support`、`coordination`、`active site`、`single atom motif` 之间还没有形成稳定的一一对应 schema。

这意味着下一阶段重点不应只放在 reaction type 或 task name 归一化上，而要继续补足“材料种类与位点构型”的经验覆盖和结构化映射。

计划主线如下：

1. 继续用真实论文样例做 surface experience 收集
   - 重点收集单原子催化剂、载体催化剂、氧化物表面、碳材料、团簇/纳米颗粒、缺陷工程材料、表面官能化材料等常见体系。
   - 将论文中出现的材料表述、位点表述、配位环境、support/facet/termination 表述持续沉淀到经验文件中。

2. 扩充 `paperread` skill 中可稳定识别的材料种类
   - 目标不是只识别“金属元素名”，而是识别更有建模意义的类别和局部结构语义。
   - 例如：
     - 单原子位点
     - M-Nx / M-Ox / M-Sx 配位环境
     - oxide-supported metal / carbon-supported single atom
     - exsolved particle / anchored cluster / defect-bound adsorbate site

   - 对论文中的材料描述建立更明确的字段拆分，例如：
     - host/support
     - active_metal_species
     - site_type
     - coordination_environment

   - 先从最常见、最可操作的体系开始，例如：
     - oxide facet + vacancy

     - supported cluster on oxide

5. 保持经验收集闭环
