## 建立 ptomodel 到 surface-modeling 参数文件的调用关系

为避免 `ptomodel` 只输出任务名却不知道如何对接参数，本日将调用链直接接入代码：

```text
paperread outputs
-> ptomodel 选择 executable task
-> ptomodel 生成 task_inputs
-> ptomodel 读取 surface-modeling/schema/task_parameter_schema.json
-> ptomodel 在 *_ptomodel.json 中写入 schema registry 和 task refs
-> downstream agent 依据 schema 填写具体参数
-> 调用 surface-modeling 脚本
```

对应修改：

- `paperread/surface/ptomodel.py`
  - 新增 `SURFACE_MODELING_PARAMETER_SCHEMA_PATH`
  - 新增 `_load_surface_modeling_parameter_schema()`
  - 在 `build_ptomodel_payload()` 顶层输出：
    - `surface_modeling_parameter_schema`
  - 在每个 document 下新增：
    - `task_parameter_schema_refs`

这样 `ptomodel` 的职责被明确为：

- 识别可执行任务
- 给出论文归一化后的 `task_inputs`
- 指向该任务对应的参数 schema

而不是直接编造最终 CLI 参数值。

## 关于其他 skills 如何整理“经验”

本日顺带检查了仓库中其他 skill 的知识/经验沉淀方式。当前并不是所有 skill 都使用 `experience/` 目录，常见形式包括：

- `references/`
  - 用于沉淀稳定参考流程、提交模板、配置说明
  - 例子：
    - `agents/Agent/skills/vasp/references/`
    - `agents/Agent/skills/vasp-pymatgen/references/`
    - `agents/Agent/skills/lammps/references/`
    - `agents/Agent/skills/dpdisp/references/`
    - `agents/Agent/skills/bohrium/references/`

- `assets/`
  - 用于放方法说明、案例文档、辅助材料
  - 例子：
    - `agents/Agent/skills/mattersim/assets/`
    - `agents/Agent/skills/materials-project/assets/`
    - `agents/Agent/skills/atomic-structure/assets/`

- `examples/`
  - 用于放示例输入结构或演示文件
  - 例子：
    - `agents/Agent/skills/surface-modeling/examples/`

- `guides/`
  - 用于沉淀概念性流程、训练指南、设计路线
  - 例子：
    - `agents/Agent/skills/guides/`

- 配置 / schema 文件
  - 用于稳定接口约束，而不是自然语言经验
  - 例子：
    - `agents/Agent/skills/vasp/references/config.yaml`
    - `agents/Agent/skills/surface-modeling/schema/task_parameter_schema.json`

可以认为：

- `experience/` 更适合持续累积、待归纳、待升级的经验记录
- `references/` / `assets/` / `guides/` 更适合稳定知识
- `examples/` 更适合输入输出样例
- `config` / `schema` 更适合机器可消费接口
