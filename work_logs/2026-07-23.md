### 调用与提交

- 每个任务使用独立目录 `mlip/<时间戳>.mace_<任务名>/`，通过
  `MACE_WORK_DIR` 同时指定输入与输出目录。

  `MACE_PYTHON_ARGS` 传入模型、设备、线程数和简单命令行参数。

- 正式 GPU 任务由 `pjsub` 调用 launcher，并通过逗号分隔的
  `-x "MACE_WORK_DIR=...,MACE_DEVICE=...,..."` 传递环境变量。
- PJM 合并日志写入任务目录中的 `mace_calc.out`。单点计算输出
  `results.json` 和 `evaluated.extxyz`；弛豫任务还输出
  `relaxed.extxyz`、`optimization.traj` 和 `optimization.log`。

## MLIP skill 接入 DeepMD/DeePMD-kit

在现有 MACE 与 UMA 支持基础上，将上一级目录中的 DeepMD 运行时和训练工作流接入
`agents/Agent/skills/mlip/`：

- `/home/pj24001724/ku40000345/wu/deepmd_kit` 作为运行时来源，提供
  `python/3.12.11`、`dp_venv/bin/dp` 和
  `deepmd_root/bin/lmp`。
- `/home/pj24001724/ku40000345/wu/deepmd_train` 作为已有训练与工作流来源，
  保存训练配置、数据、checkpoint、冻结/压缩模型和历史 PJM 任务。
- 更新 `SKILL.md` 和 `agents/openai.yaml`，使 MLIP skill 能够识别
  DeepMD、DeePMD-kit 和 DeepModel 的训练、微调、冻结、压缩、测试及
  DeepMD-LAMMPS MD 请求。

### 通用启动与环境

- 新增 `scripts/submit_deepmd_calculation.sh`，统一处理 `dp` CLI 与
  DeepMD-LAMMPS 两种模式。
- 正式执行时先加载 Genkai 的 `python/3.12.11` module，再使用绝对路径激活
  `deepmd_kit/dp_venv`，避免依赖调用 shell 中可能变化的 `HOME`。
- 默认使用 TensorFlow CPU 后端、15 个主机线程、1 个进程；当前 PJM 头不申请
  GPU，其他后端或 GPU 资源必须先单独验证。
- 支持通过 `DEEPMD_RUNTIME_DIR`、`DEEPMD_TRAINING_ROOT`、
  `DEEPMD_VENV_DIR`、`DEEPMD_BIN`、`DEEPMD_LMP_BIN`、
  `DEEPMD_WORK_DIR`、`DEEPMD_MODE`、`DEEPMD_BACKEND`、
  `DEEPMD_COMMAND`、`DEEPMD_ARGS` 和 `DEEPMD_THREADS` 覆盖运行参数。

### 预检、提交与输出

- `DEEPMD_DRY_RUN=1` 只核对运行时、工作/输出目录、后端、线程数和完整命令，
  不加载 module，也不启动训练或 MD。
- 新增 `DEEPMD_REQUIRED_PATHS`，在执行前检查输入 JSON、checkpoint、模型、
  数据目录或 LAMMPS 输入是否存在；缺失输入会直接停止。
- 每个任务使用独立目录 `mlip/<时间戳>.deepmd_<任务名>/`，该目录同时保存输入、
  模型、训练/测试结果和 `deepmd_calc.out`。
- skill 中记录了 `train`、`freeze`、`compress`、`test` 和
  DeepMD-LAMMPS 的 dry-run 与 PJM 调用方式；Agent 的 `run_skill_script`
  仅用于非计算预检。
- 训练输出名称受 `input.json` 控制，通常包括 `model.ckpt*`、`checkpoint`
  和 `lcurve.out`；冻结、压缩与 LAMMPS 通常产生 `graph.pb`、
  `compress.pb`、`log.lammps`、dump 或轨迹文件。

### 既有 nnp_train 工作流边界

- 对明确指向 `deepmd_train/nnp_train` 的续训或微调任务，保留使用已有
  `wu_deep.sh` 的约定，不在通用 launcher 中重写其多阶段逻辑。
- 提交前必须核对 `TRAIN_ID`、`INPUT_NAME`、`BASE_CKPT`、`TRAIN_MODE`
  和 `DP_TEST_N`。
- `TRAIN_MODE=init` 用于加载旧权重并重置 step/学习率，`restart` 只用于严格延续
  原 checkpoint 进度。
- 历史输出显示该专项脚本的自动重提曾遇到 scheduler wrapper 错误，因此不能仅因
  主训练阶段成功就假定自动重提可靠。
