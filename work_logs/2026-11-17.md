## 实际修改

- `src/genkai/literature/surface/extraction/extract_surface_relations.py`：一条记录写一行 JSON。
- 新增 `src/genkai/literature/surface/core/records.py`：集中读取 JSONL、历史连续多行

- `src/genkai/literature/surface/artifacts.py`：先验证输入，再保存规范化 JSONL；保留
  原始关系文件的 SHA-256。可选条件 CSV 保存为
  `stages/01_paperread/conditions.csv`，在 extraction metadata 中记录路径、哈希、来源。
- `src/genkai/modeling/ptomodel.py`：读取条件快照前检查运行目录边界和 SHA-256，
  将 CSV 传给已有映射器；artifact-backed plan 使用运行目录相对路径并保留条件引用。
- `src/genkai/modeling/mapping.py`：按文档 ID 或段落 ID 匹配 CSV；保留 PDF 入口的
  `surface_conditions_N` / `surface_relations` 特例；去掉任意按行序兜底。保存全部
  `condition_rows`，只使用不冲突的条件值补充缺失关系字段。精确文档 ID 和段落 ID
  同时匹配不同文档时不自动选择。
- `src/genkai/modeling/checklist.py`：使用共享关系读取器；把条件冲突、无法匹配的
  文档列入 `conditions` review items。这些是规划复核项，不是新增执行任务。
- `src/genkai/workflows/{surface_paper,paper_to_mlip}.py`：传递可选条件表；默认仍只准备计划。
- `src/genkai/cli.py`：离线入口增加可选 `init --conditions TABLE.csv`。
- 新增 `tests/literature/test_surface_relations_jsonl_contract.py`、
  `tests/modeling/test_condition_handoff.py`，更新两个 workflow 测试文件：覆盖格式、
  真实 writer→artifact 接线、快照、篡改、路径边界、缺失文件、多文档、冲突条件、ID 歧义、
  CLI 和 prepare-only 行为。端到端输入测试只 mock LLM 回复，不 mock artifact/规划实现。
